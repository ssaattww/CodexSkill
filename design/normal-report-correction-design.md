# 凍結前の通常報告における軽微な訂正の設計

状態: 提案中（設計の受入判断前、運用変更は未実装・未検証）。

関連課題: [親 #92](https://github.com/ssaattww/CodexSkill/issues/92)、[設計 #102](https://github.com/ssaattww/CodexSkill/issues/102)。設計の受入後に行う Skill の変更は親課題に残す。

## 目的

製品動作、仕様、検証結果およびレビュー判定を変えない報告上の軽微な指摘について、実装担当への差し戻しと文章だけの再レビューを減らす。指摘者が単独で訂正、根拠の記録、読み戻しを完結できるようにする。技術的な評価の責任や独立レビューの要件は変更しない。

## 実装方針

対象は、独立最終レビューの対象 HEAD を凍結する前の通常報告（実装報告、通常レビュー報告、検証・修正確認報告、これらの集約報告）の現行版とする。既存の証拠から意味が変わらないと確認でき、編集権限と単独の編集担当を確立できる場合に限る。

1. 指摘者が対象、凍結状態、訂正の影響、根拠を確認する。
2. 親が通常報告の編集経路で指摘者一人を編集担当として確定する。他の担当による同時編集を止め、編集前の版を確保する。
3. 指摘者が軽微な訂正をまとめて反映し、差分と新しい版を読み戻す。
4. 親が訂正完了の記録と最新の報告版を引き継ぎ、既存の通常レビュー収束・凍結前準備へ戻す。

対象外、根拠不足、版の競合、権限不足、凍結済みまたは凍結状態不明の場合は直接訂正を完了扱いにせず、親へ返す。

## 実装詳細

### 対象の判定

次の条件をすべて満たす場合だけ、軽微な訂正とする。

- 通常報告の現行版であり、独立最終レビューの凍結前である。
- 訂正前後で製品仕様、動作、実装内容、検証対象・条件・結果、指摘の識別子・重要度・必要対応、対象 HEAD、レビューの判定・根拠・評価範囲が同じである。
- 確認済みの証拠を参照でき、文書の意味が変わらないと差分から説明できる。
- 対象文書の編集権限があり、他者の GitHub レビュー本文、コメント、歴史的な証跡の書き換えではない。

| 指摘例 | 扱い |
| --- | --- |
| 誤字、脱字、同じ意味の表現の整理 | 直接訂正可 |
| 内容を変えずに見出しを整理する | 直接訂正可 |
| 確認済みの同一 HEAD・同一検証結果の証拠へのリンクの誤記を直す | 直接訂正可 |
| 新しい仕様判断、コードまたは設計変更を要する | 実装担当へ差し戻す |
| 未実施の検証を実施済みとする、結果の合否を変える、別 HEAD の証拠を採用する | 検証担当へ差し戻す |
| 指摘の重要度、必要対応、レビュー判定、未確認範囲を変える | レビュー担当へ差し戻す |
| 歴史的な報告にある重要度の転記誤り | 原本を維持し、既存の正誤記録の手順へ差し戻す |
| 他者の GitHub コメントや凍結後の独立レビュー報告・証跡を編集する | 対象外。既存の所有者と手順へ戻す |

判断が分かれる場合は軽微と推定せず、根拠を示して親に返す。単なる表現修正に見えても、判断の意味が変わる場合は対象外とする。

### 単独編集と版の管理

親は同一報告について指摘者を唯一の編集担当として明示し、対象と編集前の版を記録する。対象はリポジトリ相対の報告ファイルまたは編集可能な報告成果物の識別子、版はコミットとファイルの版、または不変の成果物版識別子で特定する。未確定の文書も編集前の内容を再取得できる版として確保し、上書きだけで旧版を失わない。

指摘者は編集直前に旧版と凍結前であることを再確認する。同時編集や版の不一致を発見したら上書きせず、親が編集担当と基準版を再確定する。編集担当は読み戻しの完了または中止まで交代させない。権限がなければ無理に編集せず親へ返す。

### 訂正記録と読み戻し

指摘者は次を一つの訂正記録にまとめ、親の通常報告管理経路に返す。

- 指摘の識別子、編集対象と単独の編集担当、編集前の版。
- 訂正箇所、理由、確認済み根拠の参照、差分（変更前後の該当箇所を特定可能なもの）。
- 訂正後の版、および保存先から再取得した版・内容の一致、差分が予定範囲内であること、参照先リンクと根拠の一致の読み戻し結果。
- 技術的な結果・判定・対象 HEAD が変わらないことの確認、完了または中止の状態と残る問題。

保存成功だけでは完了としない。指摘者自身が新しい版を取得して確認する。不一致や意図しない差分があれば完了とせず、親に返す。複数の軽微な指摘は同じ版に対してまとめ、個々の理由と差分の対応を維持しつつ、読み戻し、証拠参照をまとめて記録してよい。

報告の文章だけを理由とする実装担当への差し戻しと製品の再評価は不要とする。ただし報告変更による新たなコミットで HEAD が変わる場合、既存の HEAD に対応した検証・通常レビュー収束・凍結前の検証条件を免除しない。証拠は対象 HEAD と対応するもののみ再利用し、同じ証拠を重複して作らない。

### 責務と引き継ぎ

| 担当 | 責務 |
| --- | --- |
| [development-orchestrator](../skills/development-orchestrator/SKILL.md) | 凍結前の対象・範囲、編集担当、通常報告への経路、差し戻し先、通常レビュー収束と凍結前準備を管理する。凍結以降の終端処理を引き取らない。 |
| [review-worker](../skills/review-worker/SKILL.md) | 判定・指摘・証拠の整合と軽微か否かを判断し、指摘を返す。レビュー中に実装を変更せず、実行環境固有の保存は担わない。現行のレビュー結果を変えない指摘者としての編集は、親が権限と担当を確立した通常報告の編集経路で別に行う。 |
| [report-writer](../skills/report-writer/SKILL.md) | 提供された根拠と対象識別子に忠実な訂正文と記録を扱い、実質的な結論変更を行わない。保存やコメントの実行は呼出側の責務とする。 |
| [report-output-manager](../skills/report-output-manager/SKILL.md) と呼出側 | 通常報告の保存・版参照・担当の引き継ぎを既存経路で扱い、指摘者が許可された対象にだけ反映し読み戻せるようにする。 |
| [review-enforcer](../skills/review-enforcer/SKILL.md) | 独立最終レビューの予約、凍結、独立レビュアー、証跡コミット、最終公開と対象 HEAD の CI の唯一の終端責任者であり続ける。 |

独立レビューの製品評価、必要な検証、レビュアーの独立性は省略しない。指摘者が通常報告を編集したことを独立レビューの代わりにはしない。凍結後に訂正が必要となった場合、本手順の対象外とし、既存の `review-enforcer` の終端処理、差し戻しおよび証跡条件に従う。他者の GitHub レビュー本文・コメントは凍結前後を問わず改変しない。

## 受け入れ条件

- [ ] 凍結前の通常報告に限定して軽微な訂正の例と対象外の例を識別できる。
- [ ] 指摘者一人が編集対象と編集前の版を確定し、他の担当と同時編集せず訂正・読み戻しを完了できる。
- [ ] 理由、根拠、差分、新しい版、読み戻し結果を追跡でき、旧版を失わない。
- [ ] 実質的な仕様・検証・判定変更、根拠不足、競合、権限不足は差し戻され、他者の GitHub コメントや凍結後の証跡を編集しない。
- [ ] 既存の責務、独立レビューの要件、HEAD に対応した必要な検証を維持する。
- [ ] 複数の文章修正をまとめ、不要な実装差し戻し、製品再評価、証拠の重複を避ける。

## 確認内容（実装後の確認予定）

| 確認する条件 | 方法 | 期待結果 |
| --- | --- | --- |
| 誤字、表現、見出し、確認済み証拠リンク | 通常報告の訂正前後を比較 | 指摘者の単独編集と読み戻しで完了し、結果・判定は不変 |
| 版の競合、凍結状態不明、権限不足 | 編集開始条件と読み戻しを確認 | 上書きせず未完了として親に返す |
| 検証結果・判定の変更、他者コメント、凍結後の報告 | 対象判定と引き継ぎを確認 | 直接訂正は行われず該当担当・既存手順へ返す |
| 通常報告の訂正後に HEAD が変化 | 凍結前準備と独立レビューの証拠を確認 | 既存の必要検証と独立レビューが維持される |

この設計書だけで運用変更や上記確認が完了したとはみなさない。
