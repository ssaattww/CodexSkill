# Markdown 直接引用の用語検査例外設計

状態: 提案中。固定版ラッパーと架空入力による接続確認は実測済み。引用例外の正式機能と全 CI は未実装・未検証。

## 目的

発言者・宛先・独立した固定出典の原文と一致し、文書中の帰属も確認できる Markdown 直接ブロック引用だけを、用語検査の例外候補にする。引用の前後と引用外の同じ語は従来どおり検査する。出典の信頼性・原文を確認できない場合は通常検査を維持する。

本文に長い証明用記載は求めない。個人会話、非公開 URL、個人の PC 名、内部パス、Todo リンクや会話全文を収集・保管しない。

架空例:

```md
甲は乙に次のように伝えた。

> フラミポを確認して。

その後、甲はフラミポを一覧にした。
```

例外候補は `>` で示すブロック引用本文だけ。導入文と後続の「フラミポ」は検査する。

## 実装方針

初版は Markdown の明示ブロック引用だけを扱う。通常文との文字列一致、用語の括弧書き、鍵括弧だけの引用、コード、コメント、入れ子、曖昧な構文・帰属は例外にしない。検査対象の文書や台帳の記載だけでは出典の信頼性を自己認定できない。出典の信頼設定を変更する場合は、既存の repo 設定変更と同じ利用者確認境界を適用する。

```mermaid
flowchart LR
    Select[既存の対象選択と除外] --> Validate[引用構文・台帳・証拠を検証]
    Validate --> Mask[検証済み範囲だけ等長マスク]
    Mask --> Engines[既存の用語検査と cspell]
    Engines --> Diagnostics[元ファイル位置の診断]
```

セットアップと通常 CI は公開・私的出典を取得しない。検査開始前に、既存の確認済み設定で管理された出典 ID・固定版・内容指紋を、信頼できる呼出側から読み取り専用で受け取れる場合に限り、指定された公開固定資料だけを読み、台帳と本文を照合する。公開を確認できない資料は使わない。提案文書・台帳・その他検査対象が自身や任意入力の信頼性を宣言しても採用しない。既存環境がこの入力条件を満たすかは未確認である。新規 API・鍵・権限は設けず、資料・信頼設定を検証できない場合は通常検査を続ける。prh、他の lint、文書レビュー・承認自体は例外の対象外とする。

## 実装詳細

### 入力と承認

repo-local の証拠台帳は版番号と、項目ごとの対象相対パス、引用本文の完全一致文字列、発言者、宛先、出典 ID・固定版、文書中の引用位置と帰属を持つ。出典 ID・固定版・内容指紋に対応する同一の固定資料記録から、原文・発言者・宛先を一組として照合する。架空の「資料 v3」の一記録に発言者「甲」、宛先「乙」、原文「フラミポを確認して。」が揃っている場合に、対象文書の正確な相対パス、引用本文の位置、文書中の帰属をそれぞれ照合する。非公開情報を台帳に複製しない。JSON の `verified` 等は自己申告であり、出典の信頼性を証明しない。

出典の信頼設定や許可範囲の追加・変更・削除には既存の利用者確認境界を適用する。引用本文・パス・発言者・宛先・出典・原文・帰属は、検査時に信頼入力、固定資料、対象文書へ照合する。台帳項目の存在や変更だけでは例外を有効にしない。

検査開始前に受け取った信頼入力と固定資料を検証でき、出典 ID・固定版・内容指紋、および同一記録の原文・発言者・宛先が一致し、対象文書の正確な相対パス・引用位置・帰属も一致するときだけ候補にする。信頼入力の取得不能、資料の失効・削除、いずれかの不一致では通常検査を維持する。

### 検証と共通位置

既存 Duck 依存の公開 `@textlint/markdown-to-ast` `parse()` を解析器候補とする。他リポジトリへの依存追加はしない。今回、Duck の固定依存にある `@textlint/markdown-to-ast` 15.7.0 を架空入力で実測し、BOM 付き入力で元位置がずれることを確認した。これは採用前の限定確認である。AST の `raw` と UTF-16 `range` を元ファイル本文へ厳密に照合し、引用本文だけを特定する。BOM による原文とのずれ、遅延継続・隣接行、位置補完、その他の理由で境界を確定できない場合は候補なしとする。通常文、重複候補、入れ子引用、コード・コメント混在も無効とする。採用前に架空入力で各ケースの構造と元位置を確認し、照合不能なら例外を付けない。

共通座標は元 UTF-8 本文を厳密に decode した後の Unicode scalar value（コードポイント）オフセット `[start,end)` とする。JS の UTF-16 index、Python の codepoint index、Markdown parser の source span、Sudachi やその他前処理後の位置は、この基準へ写す offset map を持つ。map がない変換から例外範囲を作らない。マスクは改行を保持して非改行文字を空白に置換し、文字数と元位置を保つ。CRLF の CR/LF、日本語、絵文字を含む診断位置変換を確認する。

### 既存検査への接続

全 checker は同じ検証済み範囲を使う。cspell にはファイル単位のマスク本文を `stdin://<元相対パス>` として渡す前に、既存 selector の対象選択と除外を適用する。対象外 path を cspell の除外設定だけに任せない。cspell の生成設定では元 repo の設定と相対パス identity を使い、診断を元 path と元座標に対応づける。引用範囲を拡張する正規表現は使わない。

既存 CLI の全体・差分・個別選択を維持し、差分では選択されたファイル全文を検査する。台帳、信頼設定、固定資料の変更・削除・失効は差分対象として検出し、hook は「Markdown 変更なし」で抜ける前に判定する。信頼入力が変わった場合は影響する台帳項目を特定し、その対象文書に通常検査を再適用する。信頼設定や資料の前回値との比較ができず影響範囲を特定できない自動の差分検査や hook では、Markdown の差分がない場合も含め、既存の対象選択と除外設定に従う全対象に通常検査を適用し、未確認の例外は適用しない。明示的な個別ファイル指定は既存の対象範囲を維持し、信頼状態を検証できない項目には例外を適用しない。台帳項目の削除・出典の失効・削除は通常検査へ戻す。孤立項目、不正項目、必須台帳の欠落は区別して失敗させる。対象文書の移動・rename・削除は旧 path を含め台帳全体と照合し、旧例外を新 path へ引き継がない。

台帳が未導入なら従来動作を維持する。台帳が存在し壊れている場合は検査失敗とする。既存 JS/Python の stdin 動作、Python の明示 `.txt` 検査、許可一覧説明文は今回の Markdown 引用例外対象外で従来どおり扱う。

### 実測済みの接続確認と限界

固定 base の未改変 selector と cspell 9.8.0 wrapper に架空の CRLF 本文を渡した小規模確認では、selector が除外対象を外し、対象ファイルを選択した。`stdin://` wrapper 経由では fixture の元相対パスが報告され、絵文字を含む2行目にある未知語を `2:4` と診断した。wrapper 生成の whitelist 設定は許可一覧にある架空入力語を通し、別の架空未知語を診断した。これらは固定 wrapper に本文を通し、相対ファイル名・診断位置・生成設定の挙動を観測できることを示す。

この確認は既存ラッパー接続と検証の方向が実行可能である証拠に限られる。引用の正式な抽出・検証・マスク機能を実装した結果でも、全 CI や全 checker の成功でもない。cspell の正式 wrapper 接続が設定・path identity・各種座標を一般に維持すること、Unicode scalar offset への完全な変換、parser と前処理の offset map は実装前および実装時に検証が必要である。

## 受け入れ条件

- [ ] 運用側の信頼設定で指定された独立した出典の原文・発言者・宛先・文書中の帰属と、直接 `>` blockquote の本文範囲が一意に一致するときだけ、その本文を検査例外にする。
- [ ] 信頼入力は検査対象外の既存確認済み設定から呼出側が読み取り専用で供給する。取得不能・失効・削除・自己申告・不一致なら通常検査を維持する。
- [ ] 通常文、括弧書き、コード、コメント、入れ子、曖昧さ、重複、証拠不足・不一致では例外を付与せず、引用前後と引用外同語を診断する。
- [ ] 全 checker が同じ Unicode scalar 範囲を使い、元 path と元位置へ戻す。CRLF、日本語、絵文字でも位置ずれしない。
- [ ] cspell に渡す前に selector の対象選択と除外を適用し、診断時に元の相対パス・設定・位置を保つ。広域 regexp によるマスクを使わない。
- [ ] 台帳・信頼設定・固定資料の変更・削除・失効を全体・差分・hook で検出し、影響対象へ通常検査を再適用する。明示的な個別指定は既存範囲を維持する。
- [ ] 台帳未導入時は従来動作を保ち、壊れた台帳は失敗させる。stdin、Python `.txt`、許可一覧説明、prh、他 lint、文書承認は既存の範囲を維持する。
- [ ] セットアップと通常 CI はネットワークを必要としない。JSON 自己申告を出典検証済みの証明として扱わない。
