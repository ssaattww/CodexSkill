# Markdown 直接引用の用語検査例外設計

状態: 提案中。固定版ラッパーと架空入力による接続確認は実測済み。引用例外の正式機能と全 CI は未実装・未検証。

## 目的

発言者・宛先・出典の原文を確かめられ、文書中の帰属とともに利用者が正確な台帳差分を承認した Markdown 直接ブロック引用だけを、用語検査の例外にする。引用の前後と引用外の同じ語は従来どおり検査する。出典の権威性・原文に証拠がない場合は例外にしない。

本文に長い証明用記載は求めない。個人会話、非公開 URL、個人の PC 名、内部パス、Todo リンクや会話全文を収集・保管しない。

架空例:

```md
甲は乙に次のように伝えた。

> フラミポを確認して。

その後、甲はフラミポを一覧にした。
```

例外候補は `>` で示すブロック引用本文だけ。導入文と後続の「フラミポ」は検査する。

## 実装方針

初版は Markdown の明示ブロック引用だけを扱う。通常文との文字列一致、用語の括弧書き、鍵括弧だけの引用、コード、コメント、入れ子、曖昧な構文・帰属は例外にしない。台帳の申告値だけでは出典を証明できない。登録・変更時は利用者が正確な台帳差分と文書中の帰属を確認し、出典の権威性、原文、発言者、宛先を照合する。これらのいずれかが変われば再承認が必要である。

```mermaid
flowchart LR
    Select[既存の対象選択と除外] --> Validate[引用構文・台帳・証拠を検証]
    Validate --> Mask[検証済み範囲だけ等長マスク]
    Mask --> Engines[既存の用語検査と cspell]
    Engines --> Diagnostics[元ファイル位置の診断]
```

セットアップと通常 CI は公開・私的出典を取得しない。CI は既存承認済み台帳、ローカル本文、引用位置と対象ファイルの整合だけを検査し、出典の真正性を独立に証明したとは扱わない。prh、他の lint、文書レビュー・承認自体は例外の対象外とする。

## 実装詳細

### 入力と承認

repo-local の証拠台帳は版番号と、項目ごとの対象相対パス、引用本文の完全一致文字列、発言者、宛先、公開された権威資料の固定版または識別子、原文と役割を確かめる最小の公開抜粋、文書中の帰属を持つ。非公開情報を含む証拠は登録しない。JSON の `verified` 等は自己申告であり、利用者レビューの代わりにしない。

利用者承認の単位は台帳の正確な追加・変更・削除差分である。引用本文、パス、発言者、宛先、出典、抜粋、帰属の対応を一緒に示し、承認後の変更は新しい差分として再承認する。承認済み項目の削除は例外解除であり、該当箇所を通常検査へ戻す操作として扱う。

### 検証と共通位置

既存 Markdown parser が構成する `>` ブロック引用ノード本文と、台帳の引用文字列・文書中の帰属・出典抜粋が一意に一致した場合のみ有効範囲を返す。通常文に一度だけ存在する文字列、重複候補、入れ子引用、コード・コメント混在、曖昧な境界は無効とする。AST の正規化文字列のみでは照合せず、原文との一意な位置対応を必須にする。

共通座標は元 UTF-8 本文を厳密に decode した後の Unicode scalar value（コードポイント）オフセット `[start,end)` とする。JS の UTF-16 index、Python の codepoint index、Markdown parser の source span、Sudachi やその他前処理後の位置は、この基準へ写す offset map を持つ。map がない変換から例外範囲を作らない。マスクは改行を保持して非改行文字を空白に置換し、文字数と元位置を保つ。CRLF の CR/LF、日本語、絵文字を含む診断位置変換を確認する。

### 既存検査への接続

全 checker は同じ検証済み範囲を使う。cspell にはファイル単位のマスク本文を `stdin://<元相対パス>` として渡す前に、既存 selector の対象選択と除外を適用する。対象外 path を cspell の除外設定だけに任せない。cspell の生成設定では元 repo の設定と相対パス identity を使い、診断を元 path と元座標に対応づける。引用範囲を拡張する正規表現は使わない。

既存 CLI の全体・差分・個別選択を維持し、差分では選択されたファイル全文を検査する。台帳変更は差分ファイルがなくても全項目を検証する。hook は「Markdown 変更なし」で抜ける前に台帳変更・削除を確認する。承認済み項目の削除は通常検査に戻す。孤立項目、不正項目、存在すべき台帳ファイルの欠落は区別して失敗させる。対象文書の移動・rename・削除は旧 path を含め台帳全体と照合し、旧例外を新 path へ引き継がない。

台帳が未導入なら従来動作を維持する。台帳が存在し壊れている場合は検査失敗とする。既存 JS/Python の stdin 動作、Python の明示 `.txt` 検査、許可一覧説明文は今回の Markdown 引用例外対象外で従来どおり扱う。

### 実測済みの接続確認と限界

固定 base の未改変 selector と cspell 9.8.0 wrapper に架空の CRLF 本文を渡した小規模確認では、selector が除外対象を外し、対象ファイルを選択した。`stdin://` wrapper 経由では fixture の元相対パスが報告され、絵文字を含む2行目にある未知語を `2:4` と診断した。wrapper 生成の whitelist 設定は許可一覧にある架空入力語を通し、別の架空未知語を診断した。これらは固定 wrapper に本文を通し、相対ファイル名・診断位置・生成設定の挙動を観測できることを示す。

この確認は既存ラッパー接続と検証の方向が実行可能である証拠に限られる。引用の正式な抽出・検証・マスク機能を実装した結果でも、全 CI や全 checker の成功でもない。cspell の正式 wrapper 接続が設定・path identity・各種座標を一般に維持すること、Unicode scalar offset への完全な変換、parser と前処理の offset map は実装前および実装時に検証が必要である。

## 受け入れ条件

- [ ] 承認済みの出典・原文・発言者・宛先・文書中の帰属と、直接 `>` blockquote の本文範囲が一意に一致するときだけ、その本文を検査例外にする。
- [ ] 通常文、括弧書き、コード、コメント、入れ子、曖昧さ、重複、証拠不足・不一致では例外を付与せず、引用前後と引用外同語を診断する。
- [ ] 全 checker が同じ Unicode scalar 範囲を使い、元 path と元位置へ戻す。CRLF、日本語、絵文字でも位置ずれしない。
- [ ] cspell に渡す前に selector の対象選択と除外を適用し、診断時に元の相対パス・設定・位置を保つ。広域 regexp によるマスクを使わない。
- [ ] 台帳変更・削除、hook の早期終了、対象文書の移動・rename・削除を検出する。承認済み項目の削除は例外解除として通常検査へ戻し、孤立・不正・必須台帳欠落とは区別する。
- [ ] 台帳未導入時は従来動作を保ち、壊れた台帳は失敗させる。stdin、Python `.txt`、許可一覧説明、prh、他 lint、文書承認は既存の範囲を維持する。
- [ ] セットアップと通常 CI はネットワークを必要としない。JSON 自己申告を出典検証済みの証明として扱わない。
