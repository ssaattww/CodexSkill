## 対応概要

レビューで指摘された6件を、文言追加ではなく責務境界の再設計として対応した。

```text
review-policy
  -> ReviewRequest
  -> review-core
  -> ReviewResult
  -> review-result-renderer
  -> rendered text
  -> report-output-manager / GitHub adapter
```

Review判断、review lifecycle、表示、repository artifactを分離し、reviewerがMarkdown fileを直接編集しなくても完結するcontractへ変更した。

## Blocking 1: Review判断とMarkdown artifactの直接結合

### 対応

format-independentなreview contractを追加した。

- `skills/review-core/references/review-contract.md`
  - `ReviewRequest`
  - `ReviewResult`
  - contract version
  - fixed enum
  - coverage/finding/result invariant
  - renderer/artifact boundary
- `skills/review-core/SKILL.md`
  - `ReviewRequest -> ReviewResult`だけを所有
  - report path、template、file write、PR投稿、product code editを禁止
- `skills/review-result-renderer/SKILL.md`
  - `ReviewResult -> Markdown | chat response | concise PR comment`
  - verdict、finding、merge candidateを再判定しない
- `skills/report-output-manager/SKILL.md`
  - repository artifact adapterへ限定
  - `reserve_artifact`と`persist_rendered`を分離
  - existing artifact-backed callerは`reserve_artifact`を既定として維持

### 結果

reviewerはrepository filesystem、Markdown template、report pathへ依存しない。report生成またはwriteが失敗しても、取得済み`ReviewResult`は変更されない。

## Blocking 2: Review停止条件がなく範囲が無制限に拡張する

### 対応

`skills/review-policy/SKILL.md`へbounded lifecycleを定義した。

1. `initial`
   - stable scopeにつき一回
   - Blocking/Highを見つけてもplanned coverageを最後まで実施
   - findingを一括で返す
2. `fix_verification`
   - same reviewerを再利用
   - previous finding、fix、direct impact、同種欠陥だけを確認
   - 同一initial finding setにつき最大二回
3. `cold_final`
   - medium/high riskだけ必須
   - fresh reviewerまたはfresh-no-history contextで一回

次の場合は`verdict=unstable`としてreview roundを追加しない。

- cold finalでnew independent Blocking/Highを検出
- third fix verificationが必要
- repeated coverage miss
- scopeが継続的に変化
- coherentにreviewできない複数high-risk concernを一PRへ混在

`unstable`後は`design_rework`または`split_required`へ戻す。

### Merge candidate

次を満たす場合だけ`merge_candidate=true`とする。

- Blocking/Highがない
- universalとselected risk moduleがdisposition済み
- high-risk判定を無効化する`unexplored`がない
- final HEADに紐づくvalidation evidenceがある
- medium/high riskはcold final済み
- verdictが`pass`または`pass_with_held`

review skillはmergeを実行しない。

### 対応

`skills/review-policy/references/code-review-criteria.md`をcriterionの唯一の正本として追加した。

Universal core:

- `U-REQ`
- `U-SCOPE`
- `U-CONTRACT`
- `U-TEST`
- `U-EVIDENCE`
- `U-DELIVERY`

Risk module:

- `M-STATE`
- `M-INPUT`
- `M-ATOMIC`
- `M-IDENTITY`
- `M-EXTERNAL`
- `M-RUNTIME`
- `M-DOC`

review開始時に`low | medium | high`を分類し、該当moduleだけを選択する。非選択moduleのcriterion rowは要求しない。

## Medium 6: Machine-readableな完了状態がない

### 対応

`skills/review-core/references/review-contract.md`へ固定値を定義した。

Verdict:

- `pass`
- `pass_with_held`
- `fail`
- `incomplete`
- `unstable`

Coverage:

- `checked_no_finding`
- `checked_finding`
- `held`
- `not_applicable`
- `unexplored`

Follow-up:

- `none`
- `fix_required`
- `design_rework`
- `split_required`
- `external_owner`

Finding origin:

- `pre_existing`
- `introduced_by_change`
- `introduced_by_fix`
- `coverage_miss`
- `out_of_scope`

`coverage`はplanned criterion IDをちょうど一回ずつ持ち、Markdown proseから状態を推測しない。

## Codex既存フローとの互換性

`skills/sub-agent-task-manager/SKILL.md`へevidence modeを追加した。

- `artifact_backed`
  - existing implementation、investigation、verification flowの既定
  - report path/scaffoldを事前予約可能
- `structured_result`
  - `review-enforcer`が明示選択
  - reviewerへreport pathやMarkdown editを要求しない
  - `ReviewResult`をprimary outputとする

これにより、既存Codex向けartifact-backed delegationを維持しつつ、reviewだけをstructured contractへ移行した。
